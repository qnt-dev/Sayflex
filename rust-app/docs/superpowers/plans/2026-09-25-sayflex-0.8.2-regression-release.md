# SayFlex 0.8.2 Regression Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Release and install SayFlex 0.8.2 with reliable clipboard transactions and fully painted compact translation cards.

**Architecture:** Keep one clipboard transaction path for dictation and selection translation. Enumerate every advertised format, preserve every materializable format, skip only formats Windows cannot produce, and reject a non-empty snapshot if nothing can be preserved. Keep the existing Slint paragraph animation but make its target height obey the same minimum as the native window.

**Tech Stack:** Rust, windows-sys Win32 clipboard APIs, Slint, PowerShell release validation, Inno Setup.

**Spec:** `docs/superpowers/specs/2026-09-25-sayflex-0.8.2-regression-release.md`

## Global Constraints

- Work only in the existing `release-hardening` worktree.
- Preserve concurrent user clipboard changes through the existing sequence-number checks.
- Do not restore delayed formats from a non-pumping owner or weaken the dedicated STA dispatcher.
- Upgrade the installed copy in place; never uninstall 0.8.1 before 0.8.2 is installed.
- Do not publish or push externally.

## Review Focus

- Firefox advertises `application/x-moz-nativeimage` with a null handle while PNG/DIB remain readable: insertion and capture should proceed and restore the image.
- Every advertised format is unreadable: SayFlex should fail without clearing the clipboard.
- A user copies something new during insertion: the new clipboard must win.
- WezTerm uses `Ctrl+Insert` after UI Automation is unavailable and receives a captured selection.
- One-line translations and processing-only cards paint the complete 96-pixel minimum popup while longer cards still grow smoothly.

### Task 1: Tolerant, loss-safe clipboard snapshots

**Files:**
- Modify: `apps/input-host/src/clipboard.rs`
- Test: `apps/input-host/src/clipboard.rs`

**Interfaces:**
- Consumes: Win32 clipboard enumeration and the existing immutable `ClipboardSnapshot` restore contract.
- Produces: one shared snapshot policy used by both `dispatch_paste` and `capture_selection`.

- [ ] **Step 1: Write failing policy tests**

Add tests proving that a readable standard format survives an unreadable private format, while a non-empty clipboard with no readable formats is rejected.

- [ ] **Step 2: Verify RED**

Run: `cargo test -p sayflex-input-host clipboard::tests::an_unreadable_private_format_does_not_discard_readable_clipboard_data clipboard::tests::a_nonempty_clipboard_with_no_readable_formats_is_rejected`

Expected: FAIL because the tolerant enumeration policy does not exist.

- [ ] **Step 3: Implement the shared policy**

Extract enumeration into a testable helper. Treat a null `GetClipboardData` or failed duplication as an unavailable individual format, log its numeric identifier without payload data, retain every successful format, and return `InvalidData` only when the clipboard advertised formats but none could be preserved.

- [ ] **Step 4: Verify GREEN and the input-host suite**

Run: `cargo test -p sayflex-input-host`

Expected: all input-host tests pass.

- [ ] **Step 5: Commit**

Commit message: `fix(input): tolerate unavailable private clipboard formats`
