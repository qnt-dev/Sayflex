# SayFlex 0.8.0 Model Lifecycle and UI Quality Design

## Purpose

SayFlex 0.8.0 closes the remaining gaps between what the interface claims and
what the Windows processes actually do. It adds safe removal of local models,
makes model residency explicit, fixes partial hotkey registration, finishes the
Companion help, aligns the standalone translator with the main window, and
replaces mechanically generated interface copy with product-language copy in
every supported locale.

This is one release candidate. It is built, installed, and smoke-tested once
after all slices pass their own tests; intermediate commits are not releases.

## Fixed product scope

- Windows 10/11 x64 only.
- Interface locales: System, English, Russian, Ukrainian, Spanish, Brazilian
  Portuguese, German, French, Italian, and Korean.
- Chinese, Japanese, Hindi, and Arabic remain dictation/translation content
  languages, not interface locales.
- Model history, provider credentials, and application settings are never
  removed by deleting a model.
- A selected local model and a model loaded in RAM/VRAM are different states.
  The interface must never call an unloaded model “In use”.
- No public-ready claim is allowed while the exact artifact is unsigned or has
  not passed installed-artifact smoke tests.

## Model removal contract

The speech worker owns speech-model files. The translation worker owns
translation packs and the shared llama.cpp runtime. The desktop requests a
removal and renders the result; it does not delete worker-owned files.

Every installed row exposes a destructive Remove action on the right. An
installed unselected row can expose both Use and Remove. The selected row says
“In use” only while its engine is loaded; when its local provider is disabled it
says “Selected · unloaded” and still offers Remove.

Remove is confirmed in place. The confirmation names the model and the amount
of model data scheduled for removal. If the selected model is resident, the
copy also says that the local route will be disabled and the engine unloaded
first. The command is rejected while a speech recording is active; a running
translation is cancelled before the selected translation model is unloaded.

Removal is ordered:

1. cancel an installation for the same model;
2. prevent new local work for that model;
3. unload the engine and wait for the owning actor/process to acknowledge the
   drop;
4. remove only the exact catalog-owned final, receipt, partial, temporary and
   backup paths under the configured model root;
5. if the last translation pack was removed, remove the shared local
   translation runtime and its exact staging/archive/backup paths;
6. rescan the catalog and emit a result containing the bytes of files actually
   removed.

Deletion never follows an arbitrary path received over IPC. Unknown catalog
IDs and paths that escape the configured root are rejected. A partial failure
returns a typed failure and a fresh catalog snapshot so the UI reflects disk
state rather than optimism.

## Memory residency contract

Speech and translation workers emit an explicit local-engine state after load
and after unload. For speech, unload acknowledgement occurs only after the
inference actor replaces and drops the Whisper engine. For translation it
occurs only after `TranslationEngine` is dropped and its llama-server child has
been terminated and waited for.

When “This computer” is switched off in a provider chain, the corresponding
worker unloads its engine. The Models page then says that the selected model is
stored on disk but not occupying model RAM/VRAM. It does not claim an exact
amount of GPU memory was freed because WDDM does not provide a reliable
per-process measurement on all supported systems.

## Hotkey reconciliation

Applying a persisted set is per action at the Windows registration boundary.
A conflict for Pause/Resume must not unregister a successfully registered
Translate shortcut. The input host returns the actual applied bindings plus a
rejection for each failed action. Desktop persistence follows the actual
applied set and each row shows its own rejection. A user-initiated edit remains
atomic for that one action: its previous chord remains live when the replacement
cannot be registered.

## Visuals and standalone translator

When Companion is selected, the Visuals page replaces the generic native-
surface note with concise operating help: between dictations, point to the
assistant, hold Ctrl + Alt, and drag with the left mouse button. The note wraps
and remains visible at the minimum supported window size in every locale.

The standalone translator uses the same light graphite sheet, typography,
hairlines, red signal, controls, spacing and responsive rules as Settings. Its
source, processing, result, empty, unavailable and error states all remain
legible at the minimum size. Controls size to translated labels instead of
fixed English widths.

## Localization quality

English message IDs remain the source contract. Every non-English catalog is
reviewed as interface copy, not word-for-word translation. In particular:

- verbs describe the action a control performs;
- Windows and speech terminology follows native platform usage;
- “release” in audio timing means releasing the hotkey, never a software
  release;
- “local” means on this computer, not “only this”;
- provider privacy statements distinguish audio and text;
- placeholders and keyboard-chord tokens remain unchanged;
- stale catalog entries are removed.

Automated gates verify completeness, placeholders, stale entries, and a
minimum-window state matrix for every locale. These gates supplement, not
replace, the semantic review.

## Release and Store boundary

0.8.0 will produce the existing offline Inno Setup artifact and a Store-ready
MSIX experiment from the same staged file manifest. Direct EXE/MSI Store
submission is not the chosen path because it requires the publisher to sign
the installer and every PE and to host immutable versioned URLs. MSIX is the
target because Store submission supplies Microsoft signing and managed update
distribution.

The repository may prepare packaging, identity placeholders, listing copy,
privacy/support checklists and validation. It cannot create or identity-verify
the owner's Partner Center account, reserve the product name, accept legal
agreements, or submit on the owner's behalf without an authenticated owner
session. Direct-download artifacts remain not public-ready until separately
Authenticode-signed.

## Acceptance

- Unit and protocol tests cover exact-path cleanup, unload-before-remove,
  partial hotkey conflict, model-state projection, and every new wire variant.
- `cargo fmt --all -- --check`, workspace tests, `clippy -D warnings`,
  `cargo deny check`, Pester release tests, and translation checks pass.
- The exact staged files, installer, and installed copy agree by hash and
  version.
- Installed smoke covers local-to-cloud unload, reinstall after deletion,
  selected and unselected model removal, Companion help, all UI locales at the
  minimum size, hotkey conflict isolation, and translator empty/result/error
  states.
- Final status remains `awaiting user verification` until the user accepts the
  installed build.
